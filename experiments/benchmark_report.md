# 实验报告：Legacy 单次生成 vs 8-Stage Pipeline

## 实验环境

- **AI 服务**: DeepSeek v4-pro (OpenAI Compatible, `https://api.deepseek.com/v1`)
- **测试脚本**: 魔法小学 (`example_school.json`)
- **测试动作**: 3 组不同复杂度的玩家行动
  1. "我走进市集，环顾四周，观察有什么有趣的摊位和人物"
  2. "我决定和最近的商人搭话，询问最近城里有什么新鲜事"
  3. "我尝试偷偷拿走摊位上的一把匕首"
- **每组独立初始化**，确保初始状态一致
- **日期**: 2026-05-11

## 分析

### 延迟：Legacy 明显更快（3.4x）

- Legacy 一次调用完成叙事+状态，总计 ~50s
- 8-Stage 分 6-8 次调用，即使有并行仍需 ~180s
- **根本原因**：每次 API 调用有 ~15-20s 的基础 TTFT（首 token 时间），8 次调用累积了大量等待
- 并行优势被 API 并发限制抵消

### Token 消耗：8-Stage 约 3x

- 重复传递上下文（世界设定、角色信息）给多个 stage
- 每个 stage 单独处理后输出中间结果，再传给下一 stage
- Legacy 一次传递全量上下文，AI 一次返回所有内容

### 质量：8-Stage 结构更完整

- **选项质量**：8-Stage 固定生成 4 个上下文相关选项；Legacy 多为 3 个泛化选项（"继续探索"/"和人交谈"/"做其他事"）
- **场景细节**：8-Stage 产出 `scene_details`（氛围/感官/关键物品），Legacy 无此数据
- **状态推演**：8-Stage 状态推演更可靠——专用 stage 做 JSON 解析，不与叙事混合
- **叙事长度**：Legacy 叙事稍长（因为不需要从 JSON block 中分离）
- **NPC 一致性**：8-Stage 有独立的 NPC 声音校验 stage，Legacy 无

### 成本效率

- Legacy 每回合约 ~2,664 input + ~763 output tokens
- 8-Stage 每回合约 ~7,956 input + ~2,204 output tokens
- **8-Stage 成本约为 Legacy 的 3x**

## 结论与建议

### 适用场景

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| 低延迟要求（手机/弱网） | Legacy | 50s vs 180s |
| 深度叙事/完整世界模拟 | 8-Stage | 结构化输出、场景细节、更好的状态推演 |
| 流式体验 | 8-Stage | Stage 4 Compose 可流式输出，用户感知延迟 ≈ Stage 1-3 总延迟 ~50s |
| 省 token/省钱 | Legacy | ~1/3 token 用量 |
| 快速原型/测试 | Legacy | 快速迭代 |

### 优化方向

1. **减少 API 往返**：合并 Stage 5(NPC) + 6(World) 为一次调用，省去一个 ~20s TTFT
2. **规则化选项生成**：当前已有 `_generate_context_choices` 后备方案，可省掉 Stage 7 的 API 调用
3. **更快模型**：在 Stage 2/3/5/7 使用更小更快的模型（如 deepseek-chat），Stage 1/4/6 用强模型
4. **真正并行**：对于支持高并发的 API（如 GPT-4o），Stage 2||3 和 Stage 5||6 的并行可减少 ~40s
5. **Hybrid 模式**：简单动作用 Legacy，复杂动作（战斗/剧情转折）用 8-Stage
